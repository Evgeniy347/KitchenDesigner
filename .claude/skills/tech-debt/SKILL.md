Реестр техдолга — `docs/tech-debt-register.md` (создать, если нет).

## Подкоманды

- `scan` — просканировать `Assets/Scripts` на индикаторы долга.
- `add` — добавить запись вручную.
- `prioritize` — пересортировать реестр по приоритету.
- `report` — сводка по текущему состоянию.

## scan

Найти в `Assets/Scripts/**/*.cs`:
- `TODO` — посчитать и категоризировать.
- `FIXME` — баги, замаскированные под долг.
- `HACK` — обходные решения, требующие нормальной реализации.
- `[System.Obsolete]` / `@deprecated` — устаревшие API.
- Дублирующиеся блоки (похожие паттерны в нескольких файлах).
- Файлы > 500 строк (возможные god-объекты).
- Методы > 50 строк (возможная сложность).

Категории: **Architecture** (связность, неверные абстракции), **Code Quality**
(дубли, сложность, именование), **Test** (нет тестов, нестабильные, непокрытые
кейсы), **Documentation**, **Dependency** (устаревшие пакеты/API), **Performance**.

Обновить реестр.

## Формат реестра

```markdown
## Реестр техдолга
Обновлено: [дата]
Всего записей: [N] | Суммарный объём: [S/M/L/XL]

| ID | Категория | Описание | Файлы | Объём | Влияние | Приоритет | Добавлено |
|----|-----------|----------|-------|-------|---------|-----------|-----------|
| TD-001 | [Кат] | [Описание] | [файлы] | [S/M/L/XL] | [Low/Med/High/Crit] | [score] | [дата] |
```

## prioritize

Скор каждой записи = `(влияние × частота_встречаемости) / объём_исправления`.
Пересортировать реестр по убыванию скора.

## report

Сводка: всего по категориям, суммарный объём, добавлено/закрыто с прошлого
отчёта, тренд (растёт/стабильно/убывает). Отметить записи старше 3 итераций
без движения — их нужно либо исправить, либо осознанно принять с указанием причины.

## Правила

- Техдолг сам по себе не плох — это инструмент. Реестр фиксирует осознанные решения.
- Каждая запись объясняет, ПОЧЕМУ долг принят (дедлайн, прототип, нехватка данных).
- `scan` гонять регулярно, чтобы ловить новый долг.
