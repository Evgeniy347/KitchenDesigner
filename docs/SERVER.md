# Архитектура сервера

Веб-версия Kitchen Designer: ASP.NET Core 10 + Blazor Server раздаёт сайт и
WebGL-сборку, хранит проекты и работает MCP-эндпоинтом для ИИ-агентов.

## Порты

Контейнер `web` самодостаточен и открывает **два порта**:

| Порт | Назначение | Маршруты |
|------|-----------|----------|
| 8080 | HTTP — сайт, API, WebGL | Blazor-страницы, `/api/*`, `/unity/*` (WebGL-сборка из монтирования `WebGL:RootPath`), `/api/mcp/ws` (канал клиента) |
| 8081 | MCP — только ИИ-агенты | `/mcp` (настоящий MCP по Streamable HTTP), `/health` |

nginx — чистый reverse-proxy перед 8080; агенты подключаются к 8081 напрямую.

## Данные

Схема БД создаётся автоматически при первом старте (с ретраями, пока
поднимается PostgreSQL).

Сохранения проектов — **файлы** `/app/data/projects/{userId}/{projectId}.json`.
Файл и есть источник истины: у него лимит размера, валидация JSON и ротация
`.bak`-бекапов. В базе лежат только метаданные.

## Аутентификация

ASP.NET Identity; страницы входа, регистрации и профиля — static SSR. Выход
только по POST, после серии неудачных попыток срабатывает lockout. Для `/api/*`
вместо редиректов отдаются 401/403.

## Поток MCP

Сервер держит **настоящий MCP-сервер** на `http(s)://…:8081/mcp` (Streamable
HTTP). Набор инструментов генерируется из одного C#-контракта
(`Assets/Scripts/Core/MCP/Contract`, общего с Unity-обработчиком; из него же
генерируется `index.ts`).

Агент подключается и **первой командой обязан вызвать `authenticate`** с ключом
проекта из вкладки — до этого любой инструмент отвечает «требуется подключение к
проекту…».

Пользователь открывает проект во вкладке (уникальный ключ показан в верхней
навигации рядом с красной/зелёной лампочкой) и копирует ключ агенту. На
`authenticate` сервер пингует вкладку по `/api/mcp/ws`, привязывает к ней
MCP-сессию (лампочка зеленеет) и ретранслирует туда все последующие команды.

Подключение агента к локально запущенному приложению — в
[readme-mcp.md](../readme-mcp.md).
