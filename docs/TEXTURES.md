# Текстуры декоров (KitchenDesigner)

Инструкция для агента. Обязательна при добавлении любого нового декора ЛДСП /
МДФ / камня. Нарушение правила — дефект, а не «особенность текстуры».

## 1. Главный принцип: масштаб физический, не «вписать в деталь»

Текстура декора имеет **физический размер в миллиметрах** — как настоящий лист
ЛДСП. Щит 2400 мм на декоре 2000 мм показывает картинку 1,2 раза, а не
растянутую на всю деталь. Это задаётся в `MaterialDef`:

| Поле | Смысл |
|---|---|
| `tileSizeMM` | физическая **ширина** картинки, мм |
| `tileHeightMM` | физическая **высота**, мм. **`0` = считать из пропорций картинки** |

`tileHeightMM = 0` — правильное значение по умолчанию. Ставить высоту руками
нужно только тогда, когда декор намеренно непропорционален исходнику.

Разрешает размер `MaterialManager.TileMM(def)` — только он умеет достать
текстуру. `MaterialDef.TileHeightMM` картинку не видит и годится лишь как
квадратный запас для чисто цветового декора; в новом коде звать `TileMM`.

### Как выбрать `tileSizeMM`

Не «на глаз» и не 800 по умолчанию. Отталкивайся от узнаваемого элемента
рисунка и его реального размера:

1. Открой картинку, посчитай, сколько ламелей/плашек укладывается по высоте.
2. Реальная ламель дуба — 150–200 мм, бетон/камень — от размера скола.
3. Ширина = высота_картинки_в_ламелях × 180 мм × (texW / texH).

Пример: `teplyy_medovyy_dub.png` — 1920×853 px, по высоте ~5 ламелей.
5 × 178 ≈ 890 мм высоты → ширина 890 × 1920/853 ≈ 2000 мм. В каталоге стоит
`tileSizeMM: 2000`, высота считается сама.

### Цвет

У декора **с текстурой** `baseColor` = `Color.white`. URP Lit умножает
`_BaseColor` на картинку, поэтому цветной base color её перекрасит. Цвет
осмыслен только у декоров без текстуры (там он и есть весь декор) — либо как
заглушка, если файла ещё нет.

## 2. Бесшовность: обработать края ДО коммита

Картинку с необработанными краями класть в проект нельзя — при повторе на
крупном щите видна сетка стыков.

### Шаг 1. Измерить

```bash
pwsh -File tools/seam-check.ps1 -Path Assets/Resources/Textures/my_decor.png
```

Скрипт печатает `ratio` по обеим осям: разница противоположных краёв, делённая
на естественную разницу соседних пикселей.

- `ratio < 1` — шов тонет в собственном шуме картинки, годится;
- `ratio > 1` — шов виден, обрабатывать обязательно (у реальных сканов бывает 2–6).

### Шаг 2. Сшить

```bash
pwsh -File tools/make-seamless.ps1 -Path source.png -Out Assets/Resources/Textures/my_decor.png
```

Как это работает: у краёв изображение подмешивается к собственному зеркальному
отражению с весом 0,5 на самом краю и 0 на границе полосы (по умолчанию 12%
стороны, кривая smoothstep). Столбец `0` и столбец `W−1` становятся
арифметически одинаковыми — стык при `Repeat` точный. Середина картинки не
тронута, поэтому рисунок не «мылится».

Полосу можно сузить: `-BandFraction 0.06` — меньше подмеса, но резче переход.
Для JPEG есть `-JpegQuality` (по умолчанию 95).

### Шаг 3. Проверить

Прогони `seam-check.ps1` заново — должно стать `ratio < 1` (у PNG обычно ровно
`0,00`; у JPEG остаётся 0,3–0,8 из-за пережатия, это нормально).

Глазами: собери раскладку 2×2 и посмотри, не читается ли крест по центру.
Численный ноль не гарантирует отсутствия «призрака» — подмешанное отражение
может дать заметное повторение узнаваемого сучка.

**Оригинал до сшивки не коммить, но и не терять** до приёмки — положи в
`tmp-scripts/textures-orig/` (папка в gitignore).

### Чего не делать

- **Не включать `TextureWrapMode.Mirror`** вместо обработки краёв. Стык выйдет
  идеальным, но на дереве видна симметрия «бабочкой» — для ЛДСП выглядит
  искусственно.
- Не растягивать картинку до степени двойки: `nPOTScale` importer'а сделает это
  сам, а пропорции декора считаются от **исходных** пикселей.

## 3. Настройки импорта

Для `.meta` любой текстуры декора:

```yaml
  textureSettings:
    filterMode: 2   # Trilinear
    aniso: 8
  mipmaps:
    enableMipMap: 1
    wrapU: 0        # Repeat
    wrapV: 0
```

Билинейная фильтрация с `aniso: 1` смазывает столешницу и пол в кашу: они
уходят от камеры почти в плоскость. Мипмапы обязательны — без них мелкий рисунок
на дальних деталях кипит.

Текстуры, загруженные в рантайме, те же режимы получают через
`MaterialManager.ConfigureTexture(tex)` — звать его для каждой новой картинки,
руками поля не расставлять.

## 4. Два способа добавить декор

### Встроенный (в сборке)

1. Положить файл в `Assets/Resources/Textures/`.
2. Добавить строку в `MaterialCatalog._builtin`:

```csharp
new MaterialDef("my_decor", "Мой декор", "ЛДСП", Color.white, "Textures/my_decor", 2000),
```

`id` попадает в сохранения — менять его после релиза нельзя, иначе старые
проекты потеряют декор (`MaterialCatalog.Get` молча вернёт дефолтный серый).

### Внешний (без пересборки)

Положить картинку в `<папка_exe>/Resources/Textures/` и вызвать
`reload_textures` (MCP) или перезапустить приложение —
`ExternalTextureCatalog.LoadAll()` подхватит её сам.

Имя файла задаёт всё:

| Имя | Результат |
|---|---|
| `dub_teplyy.png` | «dub teplyy», ширина 800 мм, высота **из пропорций картинки** |
| `dub_teplyy_2000_890.png` | «dub teplyy», плитка ровно 2000×890 мм |

Суффикс `_Ш_В` — 2–5 цифр на размер. Без него высоту диктует картинка; это
осознанное поведение, не подставляй квадрат.

## 5. Пересчёт при ресайзе

`_BaseMap_ST` («вырез» декора) зависит от размера детали, поэтому его надо
пересчитывать при каждом изменении габаритов. Единая точка —
`KitchenElement.ApplyDimensions()`, она зовёт `MaterialManager.RefreshTiling`.

Если добавляешь тип элемента со **своим** `ApplyDimensions()`, который не зовёт
`base.ApplyDimensions()` — декор на нём будет растягиваться. Либо зови базовый
метод, либо `RefreshTiling` явно.

## 6. Известное ограничение: торцы

Деталь — стандартный куб Unity: у всех 6 граней UV `0..1`, а `_BaseMap_ST` один
на рендерер. Торец 18 мм повторяет рисунок столько же раз, сколько пласть
600 мм, поэтому кромка смазана. Чинится только собственным мешем на деталь с
UV в миллиметрах; пока не сделано — не считай это багом текстуры и не пытайся
компенсировать масштабом декора.

## 7. Тесты

Новый декор сам по себе тестом не покрывается, но при правке логики масштаба
обязательны тесты в `Assets/Tests/EditMode/MaterialTests.cs`:

- чистые функции — `ComputeTileST`, `TileHeightFromAspect`;
- разрешение размера — `TileMM` (явная высота / из пропорций / без текстуры);
- регрессия ресайза — `Resize_RecomputesTiling_DecorDoesNotStretch`.

Проверь, что новый тест умеет краснеть: временно убери исправление и убедись,
что он падает (см. AGENTS.md).
