# Технический долг

Единственный список долга в проекте. Раньше их было три — `TECH-DEBT.md` и
`TASK-units-standardization.md` закрыты и удалены 2026-09-08 вместе со всеми ссылками; выжившее
из них переехало сюда.

Список ведёт главный агент. Каждый пункт написан так, чтобы исполнитель мог взять его в работу,
не поднимая переписку, из которой пункт вырос: что не так, где, почему это важно и что считается
сделанным. Порядок — по убыванию отношения «польза / цена», а не по важности.

Перед любым пунктом: `AGENTS.md` — карта, правила в `agents/*.md`; `CONVENTIONS.md` — тоже карта,
правила в `conventions/*.md`. Unity запускает координатор, воркер работает на
`.\tools\mutation-test.ps1 -TestsOnly`.

## 1. Три пустых `catch` в `BuildInfoGenerator` — номер версии сборки врёт молча

**Где.** `Assets/Editor/BuildInfoGenerator.cs:72,89,95`.

**Симптом.** Первый глотает отказ `git rev-list --count HEAD`, и версия тихо съезжает с числа
коммитов на локальный счётчик в файле. Второй глотает чтение счётчика — версия откатывается к
`0.1`. Третий глотает ЗАПИСЬ, из-за чего две подряд сборки получают один номер, а инсталлятор
считает их одной.

**Почему важно.** Это ровно «a silent fallback is an outage» из `conventions/CORRECTNESS.md`, и
бьёт по единственному числу, по которому пользователь отличает одну выложенную сборку от другой.
В прошлом реестре техдолга этого пункта не было вовсе — нашёлся при его закрытии.

**Что сделать.** Каждый отказ либо сузить до конкретного типа с тестом на контракт (образец —
`HttpListenerShutdownContractTests`), либо заставить говорить в лог с указанием, какой именно
номер версии в итоге взят.

## 2. Общий `ElementTestBase` для `MakeFacade`/`MakeElement`

**Где.** 24 тестовых файла держат собственную копию фабрики фасада или элемента
(`AttachLinksTests`, `DrawerLinksTests`, `FacadeValidatorTests`, `RoundTripTests`,
`SceneTreeTests`, `HierarchyPanelTests` в PlayMode и ещё 18).

**Почему важно.** Двадцать четыре копии одной фабрики расходятся молча, и разницу видно только
на падении.

**Ловушка, уже оплаченная.** Механическое переименование запрещено:
`FacadeMcpTests.MakePrimitiveElement` показал, чем это кончается — базовый метод строил голый
`GameObject`, локальный примитив с коллайдером, и одинаковое имя не сводило разницу, а СКРЫВАЛО
её.

**Что считается сделанным.** Каждая фикстура прочитана и различие названо; общими стали только
буквально совпадающие тела; `build.cmd -RunTests` зелёный без падения числа тестов.

## 3. `SidebarCatalog` — 30 булевых свойств `is*` вместо таблицы данных

**Где.** `SidebarCatalog.cs:51-110`.

**Почему важно.** Каждое новое `SidebarItemKind` требует ещё одной строки: это лестница типов,
переодетая во флаги — `conventions/STRUCTURE.md` → «Element type checks live in ONE place per
layer», пункт 5 списка «How to remove a type ladder». Искать по прошлому реестру не находилось,
потому что свойства называются `is*` со строчной буквы.

**Что считается сделанным.** Вид отвечает за себя данными (набор фасетов или коллаборатор),
свойства `is*` исчезли, и есть архитектурный тест, не дающий им появиться снова.

## 4. Бойлерплейт `*FieldsEditor` — список редакторов и набор классов расходятся молча

**Где.** 24 класса `*FieldsEditor` на диске, 22 перечислены руками в конструкторе
`ContextMenuUI.cs:102`.

**Почему важно.** Опасность не в скуке, а в расхождении: это ровно «a capability table has a
twin in the contract» из `conventions/STRUCTURE.md`, и разойтись они могут беззвучно.

**Что считается сделанным.** Либо тест паритета «каждый `*FieldsEditor` на диске зарегистрирован,
и каждый зарегистрированный существует», либо список строится сам. Трогать вместе с генерацией
панелей, не раньше.

## 5. Test-only API в `ContextMenuUI`

**Где.** `MaterialPreviewActive`, `ToggleTextures`, `FindDishwasherForFacade` — живут только ради
`MaterialPreviewTests`, `DishwasherElementTests`, `ElementPropertyDiagramTests`.

**Почему важно.** Это слабее мёртвого кода: удалять нельзя, но и считать их частью поверхности не
стоит — следующий человек примет их за API.

**Что считается сделанным.** Либо каждый помечен так, что видно «это сенсор для теста, а не API»
(и это проверяет сканер), либо тест дотягивается до состояния через настоящую поверхность, а член
удалён.

## 7. Рефлексивные стражи смотрят на список типов, набранный руками

**Где.** `ElementConverterTests.Reflection_AllPublicProperties_AreCovered` перебирает
`KitchenElement, FacadeElement, AssembledFacadeElement, RadialShelfElement`;
`ElementPoolResetTests.PooledTypes()` — только `KitchenElement, FacadeElement`.

**Симптом.** Новое публичное свойство `Body` появилось у двух типов сразу. Красным стал только
фасад: `PanelElement` в списки не входит, и его свойство стражи не увидели вовсе — не потому, что
оно в порядке, а потому что этот тип им не показывают.

**Почему важно.** Типов элементов в проекте больше двадцати, список отстал молча. Это та самая
болезнь «таблица возможностей и её двойник в контракте расходятся» из `conventions/STRUCTURE.md`,
только здесь расходится сам СЕНСОР: он выглядит работающим и при этом не смотрит на большую часть
предмета. Зелёный такого стража ничего не значит, и узнать об этом можно только случайно.

**Что сделать.** Список типов строится из сборки (как это уже делает `EveryElementType`), а не
перечисляется руками; исключение — только с записанной причиной. Тест обязан доказывать, что
нашёл типы: пустой или укоротившийся список — провал, а не успех.

## Проверено и закрыто отрицательным результатом: «чистый двойник рядом с компонентом»

Аудит быстрого пути (`test-results/fast-path-audit.md`) показал, что 243 класса / 2682 теста
EditMode держатся за сцену только через `new GameObject().AddComponent<XxxElement>()`, а сценовые
фикстуры съедают 96% времени прогона. Проверялась гипотеза: вынести состояние типа в чистый
`readonly struct` рядом с компонентом и перевести тесты на него.

**Два замера, и гипотеза не подтвердилась.** `PanelElement` (тонкий лист, 22 строки) дал семь
чистых тестов и рост оболочки на одну строку — выглядело почти бесплатно. `FacadeElement` (одна
анимация, один флаг «пассажира») дал ноль: сценовых тестов было 15 и осталось 15, потому что две
дополнительные развилки позы потребовали новых зеркальных тестов на стыке. Чистый тип стоит
фиксированные 58 строк в обоих случаях. На типах со сложным состоянием счётчик уйдёт в минус.

Приём делает шов БЕЗОПАСНЕЕ, но не дешевле, и на 241 оставшийся тип не масштабируется.
Заводить его заново без нового аргумента не нужно.

**Что осталось непроверенным** — другой, гораздо более глубокий рычаг: чтобы `KitchenElement`
перестал БЫТЬ `MonoBehaviour`, и существующие тесты перестали поднимать `GameObject` вообще,
а не обзаводились двойником. Это отдельная работа другого масштаба; её цена не измерена.

Оплаченный урок из двух замеров уже записан правилом — `conventions/STRUCTURE.md` → «Lifting a
type off the scene: resolve the pose through the paired API, never through `transform`».
