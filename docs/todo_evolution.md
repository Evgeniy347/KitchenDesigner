### 1.3 Система подсказок «i» — **в работе**, P1

**Что.** У кнопок и контролов — глиф «i»; наведение или клик открывает рядом облачко с
коротким текстом «что это и зачем». Тексты — не в коде панелей, а в отдельном файле констант
(`Pure`, без Unity), ключ = идентификатор контрола. Систему проектирует Opus, наполнение
текстами — opencode. **Зачем.** Часть 3 приносит десятки инженерных полей (промерзание, шов,
запас, шаг стропил, сечение лаги); без пояснения они — числа в вакууме, и каждое новое поле
будет порождать вопрос пользователю. **Цена.** Механизм 1–2 дня; сторожа 0,3 дня; наполнение —
массовое, ~120 контролов сегодня, +40 после части 3.

Чего в такой системе легко не заметить — и что должно быть в приёмке:

| Ловушка | Чем стеречь |
|---|---|
| Подсказка обязана быть у **каждого** числового поля, где значение неочевидно; иначе система есть, а пользы нет | `HintCoverageGuardTests` по образцу `SpecificationCoverageGuardTests`: перебирает контролы всех `*FieldsEditor` и ключи `SettingKeys`, требует ключ подсказки; исключения — с причиной («Ширина, мм» причины не требует). Новое поле части 3 роняет тест, а не забывается |
| Наполнение — массовая работа opencode; её нельзя проверить чтением | Тест на текст: непустой, ≤ 200 знаков, без «TODO»/«…», не повторяет подпись контрола дословно, содержит единицу там, где поле с суффиксом. Плюс сторож сирот: константа без контрола — красный |
| Облачко — ещё один хозяин `Escape` и ещё одно всплывающее окно | Одно открытое облачко на экран; `Escape` закрывает его первым в цепочке `EscapeOwnership`; открытие по наведению — с задержкой ~400 мс, чтобы не мигать при пробеге курсора |
| На 1366×768 облачко у правого края дока уходит за экран | Переворот стороны; проверка по образцу `WindowOverflowGuardTests` |
| «i» — +16 px на строку в доке, который уже считает пиксели | Считать в `SidebarDockBudget`/раскладке строки; снапшоты `UiSnapshotGoldenGuardTests` регенерируются один раз, не по одному |
| В фоторежиме и на снимках «i» — мусор | Прячется вместе с гизмо (`UI-GUIDELINES §12`) |
| Тексты про мм, регионы, нормативы — те же вопросы, что и к правилам `FND-*` | Текст про промерзание пишется после ответа 22, не раньше; до него — «глубина, ниже которой грунт зимой не промерзает; зависит от региона» без чисел |

### 3.3 Настройки, которые заказал пользователь, — и где они живут

Ответ на вопросы 1–6, 9, 10 один: **всё конфигурируемое — контролы в свойствах элемента
или в настройках; размеры пользователь меняет руками; валидация проверяет размеры против
настроек.** Это механизм `PIP-02`. Два слоя одной величины: дефолты проекта во вкладке
`SettingsConstructionTab` (ключи в `SettingKeys`, паритет — `McpSettingsParityTests`),
значения элемента — `[Undoable]`-свойства в его `*FieldsEditor`, инициализируются дефолтами
при спавне. **Каждый такой контрол — с «i» (1.3).**

#### Промерзание — по регионам, в настройках проекта (ответ 18)

Дропдаун «Регион» в `SettingsConstructionTab`, **по умолчанию «Урал»**; не города и не голые
метры. Таблица `FrostDepthByRegion` в `Pure/Construction/`: регион → глубина, мм; поле

### 3.4 Этажность как в The Sims 2 (ответы 12, 21)

Модель пользователя: **ставим стену — это этаж; кладём перекрытие, ставим следующую стену —
следующий этаж.** Переключатель этажей — отдельный, встроенный в тулбар, не окно посреди
экрана. Высота этажа по умолчанию — **3 000 мм** (от пола до пола: 2 700 чистых + 300
перекрытия); это дефолт в «Строительстве», не константа — пользователь меняет.

| Вопрос | Решение | На что ложится |
|---|---|---|
| Сущность | `Level { id, name, floorElevationMm, heightMm }` в `ProjectData.levels[]`; `levelId` у `ElementData` (нет → первый: миграция бесплатна). «Фундамент» с отрицательной отметкой, «1 этаж» 0, «2 этаж» 3 000 — обычные записи; **мансарды нет** | `ProjectData`, `SceneRestorer`, `ElementConverter`; `MoveToLevelCommand` |
| Переключатель | В тулбаре: стрелки ▲▼ + «1 этаж» + «Этажи…» (Sims 2); `PageUp`/`PageDown`. Состояние вида — `ViewState`, не `CommandStack`; создание/удаление уровня — шаг отмены | `ToolbarUI`, `ViewState`, `HelpUI`, `EscapeOwnership` |
| Новый этаж | «+» над верхним: отметка = отметка верхнего + его высота; перекрытие (этап 5) кладётся на полигон нижнего и становится полом верхнего | `Level`, `FloorSlabElement` |
| Окно «Этажи» | `IProjectWindow` на `WindowChrome`: имя, отметка, высота (live-apply); удаление в два клика с переносом или «с содержимым» | `WindowChrome`, `ConfirmDeleteButton` |
| Что видно | Текущий — полностью; ниже — видны, не режутся; выше — скрыты (Sims 2). Настройка «Соседние этажи: показывать / приглушать / скрывать» | `SceneVisibility`, `ElementHighlighter` |
| Срез стен | `WallCutaway.ShouldLower` только по текущему уровню | аргумент-отметка |
| Камера | Цель сдвигается по Y на разницу отметок; «пол» для `UpdateFloorVisibility` = отметка уровня | `CameraController` |
| Спавн и посадка | Плоскость на отметке; `IStandsOnFloor`, `FloorSeating`, `ScrewLegAutoFit` — отметка от уровня элемента | **одно** изменение с тестом «элемент на уровне 3 000 садится на 3 000» |
| Выделение | Переключение снимает выделение; чужой уровень не ловит клик | `SelectionManager` |
| Валидация, ведомость, «Сцена», MCP | Фильтр «Этаж» в «Ошибках»; раздел «1 этаж / Стены»; дерево по уровням; `level_id` в командах и `scene_*` | `ErrorPanelUI`, `SpecItem.section`, `HierarchyPanelUI`, `McpCommandHandler` + паритет |

Порядок: данные + миграция (день) → «пол = отметка» (день, самый рискованный) → видимость и
камера (день) → тулбар и окно (день) → фильтры (полдня).

### 3.5 Вентиляция на слое портов (ответы 7, 19)

Ответ 19 ничего не отменяет: **вентзазор — слой стены** (3б, толщина настраивается), **и
вентиляция на портах остаётся** — вытяжка котельной и кухни нужна в любом случае.

**Переиспользуется как есть (цена 0):** `SnapPort`, `ISnapPorts`, `SnapPortSeat`,
`SnapNeighbourFacts`, `PortTurn`, `PipeNetwork.Build`, `PipeJoint.Connects`, `PipeRules`,
`PipeFittingSeatChoice`, `PipeFittingSizeLink`, `IMountsOnTarget`,
`PipeDocking.ReseatAfterRotation`, схема портов в свойствах. Правила соединения, которые
сейчас пишутся для труб («подача с подачей», труба в списке портов), — первый слой
`PortJoint.Connects`, который вентиляция получит бесплатно.

| Что | Что сделать | Цена |
|---|---|---|
| `PipePort.OwnerKind : PipeNodeKind`, `SizeId` по ГОСТ | Вынести в `Pure/Ports/`: `Port { ElementId, PortIndex, PositionMm, OutwardAxis, ProfileId }`, `PortNetwork`, `PortJoint`; `PipePort` — обёртка; тесты переезжают без изменения утверждений | 1–2 дня |
| `PipeNodeKind` в `switch` спеки, раскладки, имён | **Не расширять.** `DuctNodeKind {Duct, Elbow, Transition, Tee, Cap, Grille}`, `DuctFittingSpec`; общее «ноги по осям» — `Pure/Ports/LegFrame` | 2 дня |
| Сечение — только круг | `DuctProfile`: `Round(Ø)` 100…315; `Rect(w × h)`; `BoxRunMesh`; в ведомость — м² жести по развёртке | круг 1 день, прямоугольник 2 дня |
| Отвод, переход, тройник | Круглые — как у труб; прямоугольные — два короба со скосом 45°, лофт, врезка через `LegFrame` | 3–5 дней |
| Решётка | `Grille`: одна нога, рамка с ламелями; шт по типоразмеру | 1 день |
| Твист и профиль | `PortJoint.Connects` сверяет профиль; иначе `VNT-02` | 0,5 дня + тест «100×200 не садится на 200×100» |
| `VNT-01…03`, UI, ведомость | `DuctIssueCatalog`, `SceneDuctSnapshot`, `DuctFieldsEditor`, одна плитка «Фитинг воздуховода» | 3 дня |

**Порядок:** вынос `Pure/Ports/` (отдельным коммитом, до первого класса воздуховода) →
круглые + решётка (рабочая вентиляция) → прямоугольные → `VNT-*`, UI, ведомость.

### 3.7 Очереди

**В работе прямо сейчас — шесть параллельных задач**, к ним не добавлять: плеер в фоне и без
музыки; труба в списке портов + правила соединения; правило «подача с подачей»; подсветка
части элемента и зелёный призрак-превью; система подсказок «i» (1.3); ведомость T5/T2; перф
T3/T4. Их приёмка — по 1.1, 1.3 и 1.4; после приёмки — **сборка плеера** (1.4), потому что
шесть агентов в одном дереве — это ровно тот случай, когда тесты зелёные, а `.exe` нет.

**Первым после них — этап 3а: технология стены, шов, запас, счёт кирпича** вместе с вкладкой
«Строительство» (регион «Урал», высота этажа 3 000) и группой «Конструкции». Потому что это
единственный этап части 3, который не ждёт ни уровней, ни ответа 22, ни нового меша: стена
уже есть, ведомость и разделы (T5) к этому моменту готовы, признак «несущая» уже в стене, а
система «i» только что появилась — и три первых инженерных поля («Технология», «Шов»,
«Запас») станут первой настоящей проверкой её сторожей на новых контролах, а не на старых.
Всё, что 3а заводит — вкладка, группа, `Pure/Construction/`, образец «правило + таблица с
источником», — фундамент и перекрытие потом только используют. Он же даёт пользователю первое
число «сколько кирпича» за два дня, а не через две недели уровней.
