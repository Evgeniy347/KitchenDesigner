### 3.3 Настройки, которые заказал пользователь, — и где они живут

Ответ на вопросы 1–6, 9, 10 один: **всё конфигурируемое — контролы в свойствах элемента
или в настройках; размеры пользователь меняет руками; валидация проверяет размеры против
настроек.** Это механизм `PIP-02`. Два слоя одной величины с одним писателем — панелью:
дефолты проекта во вкладке `SettingsConstructionTab` (ключи в `SettingKeys`, паритет
стережёт `McpSettingsParityTests`), значения элемента — `[Undoable]`-свойства в его
`*FieldsEditor`, инициализируются дефолтами при спавне.

#### Фундамент (ответы 1–4)

| Контрол | Тип | Кто читает |
|---|---|---|
| Глубина промерзания — **дропдаун** (по значению 0,8 … 2,0 м или по городу — вопрос 18) | `[Undoable] FrostDepthMm` | `FND-01` |
| Тип грунта {песок, супесь, суглинок, глина, торф, неизвестно = худший} | `[Undoable] SoilKind` | `FND-02`, коэффициент разрыхления |
| Подушка: песок, щебень (мм), трамбовка (чекбокс) | `[Undoable] SandMm, GravelMm, Compacted` | `FoundationQuantities`, `FND-03` |
| Бетон {B15, B20, B25}; арматура Ø, шаг, защитный слой | `[Undoable] ConcreteGrade, RebarDiameterMm, RebarStepMm, CoverMm` | `FoundationQuantities` (кг), `FND-04` |
| Ширина и глубина ленты | обычные `DimensionsMM` | все правила |

Правила (`Pure/Construction/FoundationRules`, коды в `FoundationIssueCatalog` и зеркалом в
`SceneAnalyzer.IssueCatalog`):

| Код | Правило | Уровень |
|---|---|---|
| `FND-01` | Заложение < промерзания при пучинистом грунте (всё, кроме песка) | Ошибка |
| `FND-02` | Ширина подошвы < минимума для грунта и толщины стены (таблица — вопрос 22) | Ошибка |
| `FND-03` | Подушка тоньше минимума (песок или щебень < 100 мм при заданной трамбовке) | Предупреждение |
| `FND-04` | Защитный слой < 2Ø или шаг арматуры > ширины ленты | Предупреждение |
| `FND-05` | Под несущей стеной нет ленты (осевая не покрыта полилинией ленты) | Ошибка |

**Правила не меняют размеры.** Ввёл 800 мм при промерзании 1 400 — получил `FND-01` и
красную подсветку; «Минимум по промерзанию: 1 400 мм» — серой строкой только для чтения
(§9). Константы — в `Pure/Construction/*Tables.cs`, каждая с источником в имени теста.

#### Стены (ответы 5, 6)

`[Undoable] Masonry` (id из `MasonryUnit`: кирпич 250×120×65 / 250×120×88, газоблок
600×300×200, брус, каркас), `JointMm`, `WastePercent`; дефолты — в
`SettingsConstructionTab`. Одно правило: `WAL-01` — толщина не кратна формату кладки со
швом (250 / 380 / 510 для кирпича со швом 10) — предупреждение.

#### Кровля и забор (ответы 9, 10): «ставит — считает само»

| | Выводится из сцены | Спрашивается один раз (дефолт в настройках, поле в панели) |
|---|---|---|
| **Кровля** | Контур — внешний контур стен верхнего уровня или полигон пола; конёк вдоль длинной стороны (кнопка «повернуть»); площадь скатов, конёк, карнизы, водосток, число стропил, брус стропил | Тип {одно-, двускатная, вальмовая}, уклон, свес, шаг и сечение стропил, покрытие, запас % |

| Вопрос | Решение | На что ложится |
|---|---|---|
| Сущность | `Level { id, name, floorElevationMm, heightMm }` в `ProjectData.levels[]`; `levelId` у `ElementData` (нет → первый: миграция бесплатна). «Фундамент» с отрицательной отметкой, «1 этаж» 0, «2 этаж» 3 000 — обычные записи | `ProjectData`, `SceneRestorer`, `ElementConverter`; `MoveToLevelCommand` |
| Переключатель | В тулбаре сегмент «Этаж: 1 этаж ▾» + «Этажи…»; `PageUp`/`PageDown`. **Состояние вида**, не проекта — `ViewState`, не `CommandStack`; создание/удаление уровня — шаг отмены | `ToolbarUI`, `ViewState`, `HelpUI`, `EscapeOwnership` |
| Окно «Этажи» | `IProjectWindow` на `WindowChrome`: имя, отметка, высота (live-apply); «+ Этаж»; удаление в два клика с переносом или «с содержимым» | `WindowChrome`, `ConfirmDeleteButton`; `WindowOverflowGuardTests` бесплатно |
| Что видно | Текущий — полностью; ниже — видны, не режутся; выше — скрыты. Настройка «Соседние этажи: показывать / приглушать / скрывать» в `SettingsViewTab` | `SceneVisibility`, `ElementHighlighter` |
| Срез стен | `WallCutaway.ShouldLower` только по текущему уровню | аргумент-отметка, тест на одну строку |
| Камера | Цель сдвигается по Y на разницу отметок; «пол» для `UpdateFloorVisibility` = отметка уровня | `CameraController` |
| Спавн и посадка | `_groundPointInFrontOfCamera` — плоскость на отметке; `IStandsOnFloor`, `FloorSeating`, `ScrewLegAutoFit` — отметка от уровня элемента | **одно** изменение с тестом «элемент на уровне 3 000 садится на 3 000» |
| Выделение | Переключение снимает выделение; чужой уровень не ловит клик | `SelectionManager` |
| Валидация, спецификация, «Сцена», MCP | Фильтр «Этаж» в «Ошибках» (`MultiSelectDropdown`); раздел «1 этаж / Стены»; дерево по уровням; `level_id` в командах и `scene_*` | `ErrorPanelUI`, `SpecItem.section`, `HierarchyPanelUI`, `McpCommandHandler` + паритет |

Порядок внутри: данные + миграция (день) → «пол = отметка» (день, самый рискованный) →
видимость и камера (день) → тулбар и окно (день) → фильтры (полдня).

### 3.5 Вентиляция на слое портов (ответ 7)

**Переиспользуется как есть (цена 0):** `SnapPort`, `ISnapPorts`, `SnapPortSeat`,
`SnapNeighbourFacts`, `PortTurn`, `PipeNetwork.Build`, `PipeJoint.Connects`, `PipeRules`
(`PIP-01` открытый конец, `PIP-03` пересёк препятствие), `PipeFittingSeatChoice`
(«максимум связей»), `PipeFittingSizeLink` (размер выводится с трассы),
`IMountsOnTarget`, `PipeDocking.ReseatAfterRotation`, схема портов в свойствах
(`PipeFittingPortsDiagram` читает форму из спеки, не из перечисления).

**Прошито сантехникой — параметризовать:**

| Что | Что сделать | Цена |
|---|---|---|
| `PipePort.OwnerKind : PipeNodeKind`, `SizeId` по ГОСТ 3262-75 | Вынести в `Pure/Ports/`: `Port { ElementId, PortIndex, PositionMm, OutwardAxis, ProfileId }`, `PortNetwork`, `PortJoint`; `PipePort` — тонкая обёртка; тесты переезжают без изменения утверждений | 1–2 дня, чистое переименование |
| `PipeNodeKind` в `switch` спеки, раскладки, имён, шести наследников | **Не расширять.** `DuctNodeKind {Duct, Elbow, Transition, Tee, Cap, Grille}`, `DuctFittingSpec` с тем же API; общее «ноги по осям» — `Pure/Ports/LegFrame`, над ним работают `PipeFittingSeatChoice` и диаграмма | 2 дня |
| Сечение — только круг (`PipeSize`, `TubeMesh`) | `DuctProfile`: `Round(Ø)` 100…315; `Rect(w × h)`. `TubeMesh` для круга, `BoxRunMesh` для прямоугольного. В ведомость — м² жести по развёртке, не кг | круг — 1 день, прямоугольник — 2 дня |
| Отвод — дуга из цилиндров | Круглый — та же дуга; **прямоугольный — два короба со скосом 45°** (`DuctFittingLayout.RectElbow`) | 1–2 дня |
| Переход — два цилиндра | Круг→прямоугольник — лофт, ~100 строк + тест на замкнутость | 1–2 дня |
| Тройник | Три короба / врезка круга в короб через `LegFrame` | 1 день |
| Решётка — аналога нет | `Grille`: одна нога, рамка с ламелями; шт по типоразмеру. Единственный новый вид узла | 1 день |
| Твист (4 × 90°) — для круга эквивалентны | Для rect допустимы только совпадающие профили; `PortJoint.Connects` сверяет профиль; иначе `VNT-02` | 0,5 дня + тест «100×200 не садится на 200×100» |
| `PIP-*` | `DuctIssueCatalog` `VNT-01…03` — та же реализация над `PortNetwork`, второй снимок `SceneDuctSnapshot` | 1 день |
| UI, сайдбар, ведомость | `DuctFieldsEditor` (профиль, длина); одна плитка «Фитинг воздуховода» с пресетами; м.п. + м² через `IQuantifies` | 2 дня |

**Не обобщается:** вентзазор в стене — слой без устьев (этап 3б), не воздуховод
(вопрос 19); сечение по расходу — расчёт, не геометрия, не делать.

**Порядок:** вынос `Pure/Ports/` (1–2 дня, отдельным коммитом, до первого класса
воздуховода) → круглые + решётка на `LegFrame` (3–4 дня — рабочая вентиляция) →
прямоугольные (4–5 дней, откладываются без потерь) → `VNT-*`, UI, ведомость (2–3 дня).

### 3.6 Чего не хватает фундаменту сейчас

Спецификация фундамента больше не ждёт: `SpecUnit` уже знает м³ и кг, раздел — строка,
`IQuantifies` спрашивается у компонентов и получает всю сцену (для `FND-05` и «по всем
несущим стенам» это и нужно). Осталось то, что ниже, — и ничего из этого не про ведомость.

| Чего нет | Кому мешает | Где взять | Цена |
|---|---|---|---|
| **Отрицательный Y** — «пол = 0» зашит в посадку, `BasePlate` и камеру | Лента под нулём проваливается под пол или садится на 0 | Этап 1 (3.4), шаг «пол = отметка» | входит в 4–5 дней уровней |
| **Признак «несущая»** у стены | Без него «по всем несущим стенам» = по всем стенам; `FND-05` не имеет правой части | `[Undoable] LoadBearing` в `WallFieldsEditor` + `wall_*` в MCP; дефолт — вопрос 25 | 0,5 дня |
| **Осевая как источник длины ленты** | `WallCentreline` считает осевую ради кладки; ленте нужны стыки соседних стен без двойного счёта углов | `Pure/Construction/FoundationLayout` — объединение осевых в полилинии | 1 день, dotnet |
| **Вкладка «Строительство»** и `Pure/Construction/` | Дефолты промерзания, грунта, подушки, бетона, арматуры — негде хранить | `SettingsConstructionTab` + `SettingKeys` + паритет MCP; заводит этап 3а — дешевле, чем фундамент | 0,5 дня |
| **Группа «Конструкции»** в каталоге и раздел «Фундамент» в `SpecSections` | Плитке некуда встать; раздел — свободная строка (T5) | `SidebarGroupKey.Construction` + `TypeRow`; константа | 0,2 дня |
| **Каталог кодов `FND-*`** зеркалом в `SceneAnalyzer.IssueCatalog` и снимок `SceneFoundationSnapshot` | Правила без окна «Ошибки» — расчёт в никуда | Образец `PipeIssueCatalog` + `ScenePipeSnapshot` | входит в 4–5 дней этапа 4 |
